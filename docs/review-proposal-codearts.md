# codearts 交叉评审：Qoder CN《P2 擦弹 / 危险度》方案

> 评审对象：`docs/proposal-qoder-cn.md`（121 行）。基线 `HEAD a54eeed` / v0.5.3 / 398 测试。
> 本文只写评审，不改 `js/**`、不 commit、不联网。所有锚点均为本次读码复核。

## 0. 结论

**放行（条件性）**。方向、复用点、刹车设计与"预先钉死判据"的纪律都成立；但**修法清单不完整、反证式用例可能空转、成就接入点漏列**三处必须改完再进入实施。不满足则打回。

## 1. 六项口径逐项核

### ① 复用点与"零边际成本"论证 —— 成立

- `js/game.js:656-673` 的敌弹判定循环、`dist` 在 `:662`、命中判在 `:663`：**逐字核对一致**。擦弹确实可在同一循环里只加一次比较，无需第二个 `hypot`。
- `js/config.js:420 PLAYER.hitRadius = 20`（注释"便于弹幕贴身擦过"）：一致。
- `js/powerup.js:83-84` 护盾赋值、`js/hud.js:154` 护盾 HUD：一致，护盾作 v1 奖励通道的路径真实存在且无需新存档。
- **补充一个 Qoder 没写、但对我们有利的事实**：`js/game.js:661` 的 `if (player.invincible > 0) continue;` 在 `hypot` 之前，所以他"无敌期不计擦弹"的取舍是**代码现状的必然**，不是设计选择——文档里应写明"这是现状约束"，避免二期被当成 bug 反复。

### ② 不碰 `js/ui/**`、零新增 STATE —— 基本成立，但有一处边界要写清

- `js/hud.js` 不在 `js/ui/**`（`docs/existing-systems-inventory.md §8`），危险度槽走 HUD 成立；但**必须在 `js/game.js:1572` 的 `drawHUD({...})` 调用处补传字段**，否则 HUD 拿不到数据（这是 game.js 改动，不是 UI）。
- 成就：`meta.js:528 getAchievementView` → `js/ui/menus.js:706` **数据驱动渲染**，新增 `ACHIEVEMENTS` 条目（`config.js:459`）确实**不需要改 UI 代码**；但成就奖励走 `bonusStardust`，属跨局经济（见 §3 分歧裁定）。
- 零新增 STATE 成立：P2 不需要暂停/输入分派。
- **需要更正的表述**：Qoder §0 说"P3 只碰…与图鉴文案"——`js/ui/codex.js` 属 `js/ui/**`，所以 **P3 会碰 UI**；"两轴代码互不相交"成立，但不要把"两轴都不碰 UI"混为一谈。

### ③ 乘算口子与密度闸门 —— 成立，但一条断言要改

- "不发分、不发经验、不发明子弹"的刹车成立；`score` 是 `levelFromScore` 唯一输入（`js/game.js:454-456`）也核对无误。
- 密度闸门：P2 不改 `setHostileBulletBudget` 额度（`js/bullet.js:213`）成立。
- **断言过弱**：Qoder 写"开启 P2 后同屏敌弹峰值**不高于**关闭时"。P2 不改变生成，固定 seed 下峰值应当**逐位相等**；"不高于"会放过"确实改变了生成"的回归。应改为同 LCG/同帧数的**精确相等**（`peakBullets`、`emittedWaves`、`emittedBullets` 三项）。

### ④ 默认路径逐位一致 —— 方案成立，反证式用例需加前提

- `else if` 插在命中判之后、且只在 `graze` 为真时执行 → 关闭态控制流不变，800/2400 帧快照可验证。
- **"把 `grazeRadius` 设成 `hitRadius` 同值、用例必须变红"这条本身可落地，但存在空转风险**：如果用例场景里没有"恰好落在 20<dist<34"的敌弹，两种配置下计数都是 0，用例照样绿——这正是"smoke 报 OK 却从未进对局"的同族空证。
  **必须钉死探针**：用**一发固定敌弹**（如放在玩家正上方 `dist=27` 处）断言 `grazeCount===1`；把 `grazeRadius=20` 后同一场景断言 `===0`。这才证明环被走到。
- 与快照不冲突：反证用例是单元级 fixture，快照跑的是"参数关闭"路径，两者不同进程，互不影响。
- **需更正的事实**：文中"新增模块必须同步 `deploy-versioning` 产物计数（30→31 的先例）"已过期——v0.5.3 基线是 **31**，新增 `js/modes/graze.js` 应为 **31→32**（`test/deploy-versioning.test.mjs:98/102`）。

### ⑤ 成本与首版边界 —— 认可 S，但边界要再收一格

- P2=S 合理（纯逻辑模块 + 3 处挂钩 + HUD + 测试）。
- 首版 6 项里，"成就 1~2 条 + `bestDanger` 本地纪录"建议**移出 v1**：成就奖励发星尘（跨局），`bestDanger` 要进 `metaData`（新存档字段 + 旧档默认值 + 落盘），两者都会把"零 UI 的纯局内机制"拖成"元进程改动"。v1 只保留：判定环 + 计数器 + HUD + 满槽护盾（双硬顶）。成就与纪录留二期，和收益裁定一起做。

### ⑥ 依赖阻塞项 —— 成立

不依赖 P-D；纯确定性判定，无随机、无回放。

## 2. 分歧裁定（v1 收益通道：星尘兑换 vs 满槽护盾）

**裁定：v1 采纳 Qoder 的「满槽 → 1 层护盾」，星尘兑换降为二期。** 我在自己的方案里主张过"+20 星尘/局"，看完证据后**修正自己的立场**：

1. `bonusStardust`（`js/meta.js:266-271`）**没有任何"每局上限"口径可复用**——它是无条件 `+= amount` 并 `saveNow()`；要做到"+20/局封顶"必须新增局内计数器（或多一个 meta 字段），成本与回归面都比护盾大。
2. 星尘是**跨局货币**（`META.stardustPerScore=400`，`js/config.js:428`，一局 2 万分≈50 星尘），可换永久强化；虽然不直接进 `score`，但属"经济→更强→更高分"的间接回路，需要在无遥测条件下做经济审计。护盾是**局内资源**，有 `maxShield` + `DANGER.capPerRun` 双硬顶，且完全随对局结束消失，可回滚性最好。
3. 因此：**v1=护盾（capPerRun 建议 3，叠加 `player.maxShield`）；二期再评估星尘兑换，届时必须同时给"每局上限字段 + 换算率 + 10 局星尘增幅审计"。**
4. 补充边界：护盾奖励会间接延长存活→更高分→更高难度（Garegga 同构），但有 cap 3 层，且不掉落/不改生成；比星尘路径更可控。

## 3. 三条最需要改的点（进入实施前）

1. **`_grazed` 修法清单补全 + 行号更正。**
   现状是 **5 处**（不是 3 处）：`allocBullet` 新对象字面量（`js/bullet.js:20-34`）、`freeBullet`（`:52-66`）、`fireBullet`（`:90-157`）、`spawnSplitBullet`（`:160-181`）、`createHostileBullet`（`:246-268`）。
   文中 `:57-63`（实为 freeBullet 内）、`:175-178`（split）、`:259-262`（hostile）**块归属与行号均需更新**。
   最小充分修法：`allocBullet` 初值 `_grazed:false` + `freeBullet` 清零 + `createHostileBullet` 清零；`fireBullet`/`spawnSplitBullet` 一并清是为了"字段生命周期一致"（否则 `_grazed` 只存在于用过的对象上，属隐式字段）。缺 `freeBullet` 是最危险的一处——跨类型池复用会让复用弹永远不计擦弹且不报错。
2. **反证式用例必须带固定 fixture（见 §1-④）。** 追加两条断言：① 固定单弹 `dist=27` 时计 1 次；② 命中当帧不计擦弹（同弹命中与擦弹互斥）。否则"改半径就变红"可能是空转。
3. **成就/纪录接入要么列全调用点，要么按 §1-⑤ 移出 v1。**
   若坚持 v1 含成就：`checkAchievements` 在 `js/game.js:1115 / :1229 / :1244` 三处被调用，`runGraze` 必须三处都传，`meta.js:504-516` 的 `view` 也要加字段；漏一处 = 该路径永不成就且无报错。若采纳"移出 v1"，则本条降级为二期备注。
   同时把 §1-③ 的"峰值不高于"改成"固定 seed 精确相等"。

## 4. 放行条件

- 三条 must-fix 落到文档（或实施计划）里，尤其第 1 条；
- **Loomy 的实证判据先出数**：若"每局擦弹 <20 次或满槽 <1 次"，按 Qoder 自己的预设判据降级为纯度量，不得硬上护盾；
- 默认 800/2400 帧快照 + smoke 四路径 + `?graze=1` 真机探针（state:1、0 报错）三项齐备后，才可进入上线流水线。
