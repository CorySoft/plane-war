## 一、方法与边界（先声明，避免误读绝对值）

| 项 | 设定 |
|---|---|
| 浏览器 | Playwright 1.62.1 / headless Chromium |
| 渲染后端 | **SwiftShader 软件光栅（无 GPU）** |
| 逻辑分辨率 | 480×720（CSS），DPR 1 / 2 两档（游戏自身已把 DPR 钳到 ≤2，`game.js:110`） |
| 场景 | 峰值：`setLevel(14)` + 全技能满 + 常驻 madHunt + 自动瞄准 + 无敌（避免死亡中断） |
| 采样 | rAF 帧间隔直方图；插桩模式单独 60s 统计绘制调用 |
| 低端模拟 | CDP `Emulation.setCPUThrottlingRate = 4` |

> **绝对值边界**：headless 无 GPU 时 Canvas 2D 走 CPU 软件光栅，帧率显著低于真实 GPU 设备。本文数字应读作「最差环境下的下界 + 变量间的相对关系」，**不能直接当作手机/桌面的真实帧率**。凡涉及「是否可玩」的结论均标注需真机复核。

## 二、绘制层量化基线（本次新增，此前只有逻辑层基线）

### 2.1 帧间隔（每档 20s，菜单 8s）

| 场景 | p50 | p95 | p99 | p50 fps | >16.7ms | >33ms |
|---|---|---|---|---|---|---|
| 菜单 1x | 15.4 ms | 19.4 | 34.5 | **64.9** | 13.9% | 2.4% |
| 峰值 1x | 19.8 ms | 34.9 | 36.1 | **50.5** | 90.4% | 7.5% |
| 峰值 2x | 64.1 ms | 85.4 | 116.0 | **15.6** | 100% | 100% |
| 峰值 1x（关 shadow） | 17.5 ms | 33.5 | 35.8 | **57.1** | 69.2% | 5.5% |
| 峰值 2x（关 shadow） | 59.1 ms | 71.4 | 85.2 | **16.9** | 100% | 100% |
| 峰值 2x + CPU 4x | 270.1 ms | 343.1 | 373.6 | **3.7** | 100% | 100% |

**读法**：
- 菜单接近满帧（64.9fps），说明 UI 静态页本身不重。
- 峰值 1x 掉到 50.5fps，1x→2x 帧时间 ×3.24（像素 ×4）→ **首因是像素填充率，不是 draw call 数量**。
- 关掉 shadowBlur 只提升 8~12%（1x 50.5→57.1，2x 15.6→16.9）→ **shadowBlur 是次因，不是主犯**；此前「子弹多时关 shadow」的降级策略是对的，但不足以解决高 DPI 成本。
- CPU 4x 下 3.7fps 是极端下界，仅用于说明低端设备余量很薄。

### 2.2 每帧绘制调用（峰值 2x，插桩 60s）

| 调用 | 次/帧 |
|---|---|
| `fill()` | 64.4 |
| `stroke()` | 28.3 |
| `drawImage()` | 13.1 |
| `createLinearGradient()` | 0.7 |
| `createRadialGradient()` | 4.6 |
| **其中带 `shadowBlur>0` 的绘制** | **22.4**（fill 13.2 / stroke 5.5 / drawImage 3.6） |

- 每帧约 106 次基本绘制 + 5.3 次渐变创建，属于「不算失控但高 DPI 下偏重」的量级。
- 22 次/帧 shadow 绘制与既有降级策略不矛盾：子弹多时关（`bullet.js:490`）、道具多时关（`powerup.js:166`），剩余来自护体弹（≤6 颗，`player.js:506`）、HUD 连击条/红心（`hud.js:74,88`）、爆炸闪光等。

### 3.2 皮肤系统事实（与「44 皮肤」的常见表述有出入）

| 事实 | 证据 |
|---|---|
| 只有 **1 套生效皮肤**（neon），不是 44 套可选皮肤 | `assets.js:13` `SKIN_STYLE = "neon"` 硬编码；无换肤 UI/菜单入口 |
| 「44」是**贴图 id 数**（MANIFEST 条目） | `assets.js:15-66`：6 战机 + 6 敌机 + 3 Boss + 2 背景 + 15 道具 + 12 技能 = 44 |
| `realistic/`、`toon/` 是**零引用死资产** | 全仓仅 `assets.js:8` 注释举例出现；共 4 张、**248 KB** |
| 加载方式：**整包同步预加载** | `game.js:122` 顶层调用 `preloadSkin()`；`assets.js:76-90` 一次 `new Image()` 全部 44 张，无按需/无优先级 |

### 3.3 首屏加载（生产环境实测）

| 指标 | 数值 |
|---|---|
| HTML + 静态资源 `load` | 788 ms |
| **`gameReady`** | **2.32 s** |
| **44 张贴图全部 `ok`** | **4.49 s** |
| skin 传输量 | 2,132 KB（总资源 2,264 KB） |
| 最慢单张 | `skill_scatter.png` 2,180 ms（仅 21 KB，受 Byethost 并发/带宽限制） |

**衍生风险**：2.32s 游戏已可玩、4.49s 贴图才齐。这 2 秒窗口里 `getSprite()` 返回 `null`，部分元素先走程序化占位绘制、随后切换为贴图 → 低端网络下会出现**可见的贴图 pop-in**。本地服务器窗口很短，生产实测窗口约 2s。

## 六、结论与优先建议

1. **没有 P0**。视觉反馈体系比预期完整：低血红光、震屏、粒子、购买/装备/解锁/任务反馈全部存在。
2. **最值得先做的两项**：P1-1（删 248 KB 死资产，零风险）+ P1-2（贴图分批加载，消除生产 2s pop-in）。两者都不碰渲染主循环，回滚成本低。
3. **P1-3 需要真机数据**：当前 15.6fps 是 SwiftShader 下界，不能作为降 DPR 的依据；建议先用真实手机/带 GPU 桌面测一轮，再决定是否动 `shadowBlur`。
4. P2 四项均为 XS 级、可随任意一次上线捎带；其中 P2-1（受击红闪）对高难度弹幕的可读性收益最直接。

## 收官状态（待随 v0.4.3 上线）

**已实施**：删除 `realistic/toon` 4 张死资产（235,300 B；`git status` 4 个 D）；贴图三批加载（14 核心 / 3 Boss 延后 2s / 27 图标延后 3.5s）；渐变缓存（星云按 4 逻辑 px 位置桶、低血按当前 transform 矩阵键控、每 ctx 上限 128 条）。

**终值复测（收官流水线独立复跑，60s 插桩）**：渐变创建 **1.13 次/帧**（linear 0.51 + radial 0.62），较优化前约 5.3 次/帧下降 **~79%**；菜单 1x **66.2fps**、峰值 1x **50.0fps**、峰值 2x **15.9fps**、2x+CPU4x **3.7fps**，与基线持平（噪声内）。
> 与上表 1.57 次/帧的差异来自采样窗口与场景随机性，两者均为真实测量；结论以「量级从 ~5 降到 ~1、帧率不变」为准。

**暂缓/待办**：高 DPI GPU 真机复测（SwiftShader 下界不作依据）、webp 资产管线；远端死资产清理在本次上线成功后按「备份先行」纪律执行。
