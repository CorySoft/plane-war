## 一、链路梳理（代码事实）

| 环节 | 实现 | 位置 |
|---|---|---|
| 触发条件 | **只有携带 `explosion` 行为的子弹"击杀"敌机时**触发；命中未死不解爆 | `js/game.js:714` |
| 爆炸行为来源 | `isExplosion` 参数 或 `explosionBaseChance 0.10 + expChance×0.10` 随机（满级 70%） | `js/bullet.js:610-620` |
| 爆炸半径 | `r = clamp(info.radius × (0.6+0.4×scale), 50, 250)`；`info.radius = 40 + expRange×12`（满级 112） | `js/game.js:818`、`bullet.js:145` |
| 体型缩放 | `scale = clamp(r/16,0.8,4) × clamp(√maxHp,1,6) × (Boss?2.5:1)` | `game.js:812-815` |
| AOE 伤害 | `aoeDmg = max(1, round(dmg × (expDmgRatio+shop) × (0.5+0.5×scale)))`，`expDmgRatio = 0.45 + expDmg×0.15`（满级 1.35） | `game.js:821` |
| 判定半径/中心 | `hypot(other, e) < r`，中心 = **死亡敌机位置**（与视觉同中心） | `game.js:841-842` |
| 尸体过滤 | `other === e` 与 `other.hp <= 0` 均跳过，不会对尸体二次计伤 | `game.js:837-840` |
| 连锁 | 被 AOE 命中者写入 `_deathExplosion`；死亡后 `depth+1` 递归；`depth >= explosionMaxChainDepth(2)` 停止递归 | `game.js:854,903-904` |
| **连锁伤害** | **`aoeDmg` 不随 depth 递减**（只有粒子/波纹视觉按 `0.5^depth` 递减） | `game.js:821` vs `826` |
| 视觉 blast | 半径 `rMax × (1-t)`，从 0 膨胀到真实 `r`，历时 0.15s | `game.js:1349-1371` |
| 视觉 ring | `rMax = r × (1.1 + 0.35k)`，k=0/1/2 → **1.1r~1.8r** | `game.js:864-866` |

## 二、视觉 vs 判定 对照

| 维度 | 判定 | 视觉 | 结论 |
|---|---|---|---|
| 最大半径 | 112（满级 expRange，small 敌机） | blast 112 / ring **123~202** | blast 一致；**ring 比判定大 10%~80%** |
| 中心 | 尸体位置 | 同位置 | ✅ 一致 |
| 生效时机 | **命中第 1 帧瞬时** | 第 9 帧（0.15s）才膨胀到 112 | ❌ **视觉滞后约 133ms** |
| 连锁时机 | 同帧递归完成 | 各层 blast 同帧推入、同步膨胀 | ❌ 首帧全屏同时爆 |

## 三、实测数据（确定性场景）

### 3.1 边缘表（r=112）

| 中心距 d | 是否命中 | 掉血 |
|---|---|---|
| 102 | 是 | -1/-7 |
| 111 | 是 | -7 |
| **112** | **是**（边界含浮点误差） | -7 |
| **113** | **否** | 0 |
| 122 | 否 | 0 |

判定边界 = 112~113，与 `r=112` 一致（`d < r` 严格小于，112 命中来自浮点/位置抖动）。

### 3.2 远距连锁

| 场景 | 结果 |
|---|---|
| A、B 相距 **274 = 2r+50** | A 死、B 不掉血、仅 1 次爆炸 → **远距不连锁** |

### 3.3 连锁深度与速度（10 架、间距 56 < r）

| 指标 | 值 |
|---|---|
| 一次击杀后第 1 帧死亡数 | **7 / 10** |
| 第 2~6 帧新增死亡 | **0** |
| 爆炸次数 | 4~5 |
| 递归深度上限 | `explosionMaxChainDepth=2` → 最多 3 层（同层可并发多次） |

**结论：整条连锁在第 1 帧全部结算完毕**，视觉上第一层波纹还没扩散，远处已连环爆。

### 3.4 时序

| 事件 | 帧 |
|---|---|
| 目标敌机掉血（AOE 生效） | **第 1 帧** |
| blast 视觉半径达到真实 r | **第 9 帧**（0.15s×60） |

## 四、结论：用户疑点成立，但不是"判定半径大于视觉"

用户描述「敌机爆炸后余波没到其他敌机就引发伤害或爆炸连锁」由两个**时序/呈现问题**叠加造成，而非判定半径写错：

1. **伤害瞬时结算 vs 视觉 0.15s 膨胀**（主因）。敌机在闪光扩散到它之前就已掉血/死亡，产生"没碰到就炸了"的观感；数据上伤害第 1 帧、视觉第 9 帧。
2. **连锁同帧完成**（加剧）。首帧 7 架同时死亡、4~5 次爆炸同一帧推入，玩家看到"波纹未扩散、远处全爆"。
3. **反向误判**：ring 视觉半径 1.1~1.8r > 判定 r，又会让玩家以为"波纹扫过却没伤害"。

非缺陷项（已核实）：
- 判定中心 = 尸体位置 = 视觉中心 ✅
- 已死/已移除敌机被 `hp<=0` 过滤，不会二次计伤 ✅
- 深度上限 2（3 层）存在 ✅
- 远距不会连锁 ✅

## 五、修复与数值建议（待裁定，未实施）

| 优先级 | 建议 | 改动点 | 成本 |
|---|---|---|---|
| **P1** | **视觉与判定时序对齐**：blast 首帧直接画真实半径 r，仅做 alpha 淡出（不做 0→r 膨胀）；或把膨胀改为首帧 70% r、0.06s 到 100%（缩短滞后） | `game.js:1351-1353` 的 `radius = rMax*(1-t)` | **XS** |
| **P1** | **连锁视觉错峰**：depth≥1 的 blast 延迟 30~50ms 再开始绘制（逻辑仍同帧结算，只错开视觉），消除"首帧全屏同时爆" | `fxBlasts` 增加 `delay` 字段，绘制时 `t` 减去 delay | **S** |
| **P2** | **ring 半径与判定统一**：`rMax = r`（去掉 1.1~1.8 倍），或保留装饰但 alpha 减半并标注为"余波" | `game.js:866` | **XS** |
| **P2** | **连锁伤害递减**：`aoeDmg *= 0.7^depth`（当前每层同伤害，仅靠深度上限防滚雪球） | `game.js:821` | **XS** |
| **P2** | `_deathExplosion` 在敌机被非爆炸弹击杀时不会触发（无害），可在命中非爆炸弹时清空该标记，避免状态残留 | `game.js:714` 附近 | **XS** |

**数值建议**：`explosionMaxChainDepth=2` 已限制 3 层；若担心滚雪球，优先做「每层伤害 ×0.7」而不是继续降深度——因为深度上限会导致高血量敌机杀不死时连锁中断，而伤害递减更平滑。

## 六、证据边界

- 全部数据来自真实 `game.js` 帧循环 + 调试接口（`spawnEnemy`/`fireBullet`），固定场景、无随机地形；暴击随机影响 AOE 伤害数值（表中 -1/-7 差异），但不影响命中几何与时序结论。
- 视觉半径取自代码公式（`rMax`），未做像素测量；时序取自帧计数（第 1 帧命中、第 9 帧视觉到 r）。
- 场景已排除玩家自动射击与升级弹窗干扰（测试敌机置于玩家下方、玩家技能全满）。
