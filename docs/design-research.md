# 玩法、关卡与数值设计：业界方案调研

调研日期：2026-11-07。本文区分「来源直接描述的事实」与「面向 plane_war 的待验证建议」；商店文案能证明游戏提供了哪些机制，不能证明这些机制带来多少留存。

## 结论摘要

| 主题 | 可核验观察 | 对 plane_war 的启示 |
|---|---|---|
| 关卡节奏 | 关卡设计资料建议用 beat sheet 编排事件、强调与休息，并以 teach → test → twist 逐步变化；这是一种可用方法，不是固定行业模板。[1] | 先做可读的节奏段：新威胁教学、重复验证、组合变化、喘息/奖励、精英或 Boss；不要只提高全局生成率。 |
| 街机复玩 | Raiden IV 的发行页列出 Arcade、OverKill、Score Attack、Boss Rush 等模式。[6] | 复玩目标可以来自规则/评分/模式变化，不必全部依靠永久加数值。发行页无法证明哪种模式提高了留存。 |
| 短波次与构筑 | Brotato 官方商店说明单波 20–90 秒、波间商店、整局少于 30 分钟，并提供可选角色、道具构筑与敌人参数可调选项。[4] | 「短波次 + 间歇决策」适合网页短局原型；这些时长是 Brotato 的产品选择，不是所有移动游戏的标准。 |
| 跨局成长 | Vampire Survivors 官方页面描述跨局收集金币购买升级，并建议集中升级武器、尝试不同升级路线。[5] | 可以试验「局内构筑 + 轻量跨局解锁」，但应优先解锁新选择，而非无限叠永久伤害。商店描述不构成留存因果证据。 |
| 挑战/心流 | GameFlow 将挑战、技能、目标清晰度、反馈、控制等列为体验维度；原研究的初步验证是对两款 RTS 的专家评审，不是射击游戏数值公式。[2] | 难度要同时看弹幕威胁、玩家可读性、反馈与操作空间，不能只看敌机 HP。 |
| 动态难度 | Hunicke 的 DDA 论文讨论依赖游戏状态自适应调整挑战的设计方向。[3] | 可把自适应当作可选实验，但要透明、缓慢、按波次更新；不要在一组已发射弹幕中途改弹速。 |
| 元进程数据 | Hamari 的研究标题与摘要描述的是徽章对用户活动的现场实验，不是免费网页射击游戏的 D1/D7 留存提升。[7] | 对成就、图鉴、排行榜、每日挑战的可迁移留存提升数字：**未检索到可靠且同类可比的公开数据**，不要承诺固定百分比。 |

## 建议的可测试原型

以下数值/公式是设计起点，不是引用的行业标准；应先埋点并通过小规模测试校准。

### 1. 一局做成有起伏的节拍，而非平滑加压

建议先做一条「短出击」：以 3–5 分钟为待测时长假设，分成若干短波次，波间给一次升级/整备；章节版则把多次出击串成「小关卡 → 章节 Boss」。短局假设需要用玩家实际完成率、退出点和重开率验证；Brotato 的 20–90 秒波次与波间商店只证明这种模块化形式可行，不证明其长度适合本项目。[1][4]

| 节拍 | 设计目的 | 约束 |
|---|---|---|
| 教学波 | 单独展示一种新弹道或敌机行为 | 同屏只引入一个主要新读屏任务 |
| 验证波 | 让玩家用熟悉操作处理同一威胁 | 保留可躲避空间，不只堆 HP |
| 组合波 | 将已学威胁与旧敌种组合 | 一次增加一个主要复杂度维度 |
| 喘息/整备 | 让玩家读懂奖励、调整构筑 | 在下一次高压前给清晰反馈 |
| 精英 / Boss | 提供章节记忆点与技能检验 | 先展示攻击预告，再进入高压段 |

这套节奏对应 [1] 的 beat / rest / teach-test-twist 思路；Boss 作为 set piece 也是该资料列出的安排方式。不同波次的目的应写进关卡表，而不是仅从难度曲线推导。

### 2. 难度用三轴调，DDA 放在波次边界

用单一难度因子 \(D\in[0,1]\) 控制三个独立参数，保留弹幕几何与预告时间：

```text
弹速       v(D) = v0 × (1 + αD)
弹幕密度   ρ(D) = ρ0 × (1 + βD)
容错窗口   g(D) = g0 × (1 - γD)
```

`α/β/γ` 是待测系数，分别调参；一次只改变一个轴，先校准可读性与躲避空间，再校准压力。不要把“更多弹、更快弹、更少容错”同时拉满。

若试验 DDA，可用上一波实际掉血量 \(L\) 与目标预算 \(L_t\) 做小步更新：

```text
e = (Lt - L) / max(Lt, ε)
Dnext = clamp(D + K × e, Dmin, Dmax)
```

玩家损血高于目标时 \(e<0\)，下一波降低挑战；反之小幅提高。`K`、上下限和目标预算均需实测；应限制单波变化量，并保留固定难度/关闭自适应选项。该式是基于 DDA 思路的本项目实验方案，不是 [3] 给出的通用参数。

### 3. 用击杀时间检查 DPS 段位墙

先统一有效 DPS 口径：

```text
DPS_eff = Σ(单发伤害 × 每秒射击数 × 命中率 × 有效开火时间占比)
TTK     = 敌人 HP / DPS_eff
```

把普通敌、精英、Boss 的 TTK 与其实际暴露/可攻击窗口 \(W\) 对比；若合理构筑在窗口内只能靠 Bomb 才能击杀，或成长一级后 TTK 突然跨越多个波次，应复核攻击窗口、伤害成长与敌人 HP。Bomb 的收益可用「节省秒数 = Bomb 对目标的有效伤害 / 基线 DPS」比较；同时单独测量其清场、救命和打断价值，避免把 Bomb 退化成唯一正确的伤害技能。这里是可复算的平衡指标，不是业界固定阈值。

局内升级可先采用可解释的小幅增量、软上限和有限槽位；乘法叠加留给少量构筑协同并设上限。Brotato 的多武器/道具选择和波间商店、Vampire Survivors 的局内选择与跨局金币升级，展示了「短期选择 + 构筑差异」的产品做法，但没有公开证据证明某一种线性/指数经济曲线普遍带来更高留存。[4][5]

### 4. 随机奖励强调可控性，避免把“保底”说成留存保证

可先测「每次给 3 个候选、限制连续重复、提供有限 reroll」；对关键流派组件可实验连续未出现后的软保底，并记录候选池、reroll 使用率、构筑完成率和失败原因。随机种子固定的挑战可用于公平比较分数。具体保底次数、权重以及它是否提升回访：**未检索到适用于本项目的可靠因果数据**；这些应作为公平性/可玩性假设做对照测试，而不是作为留存承诺。

### 5. 元进程先服务内容发现，再验证留存

| 功能 | 适合验证的产品假设 | 证据边界与建议指标 |
|---|---|---|
| 成就 | 为不同操作提供短目标 | [7] 是徽章与用户活动的现场实验，但对象与指标不等同于本项目的游戏留存；记录成就曝光/完成后行为，不引用其作为 D7 uplift。 |
| 图鉴 | 帮助玩家识别敌机与弹道 | 未找到同类、可复现的留存 uplift 数字；观察图鉴打开率、条目解锁、之后对该敌型的死亡率变化。 |
| 排行榜 | 为 mastery/score attack 提供可比较目标 | Raiden IV 商店页列有 Score Attack 等模式，但没有给出排行榜的留存因果数据。[6] 本项目先做本地成绩；线上榜须另行设计可信的成绩校验。 |
| 每日挑战 | 提供可重复、可比较的短任务 | 未找到免费网页弹幕游戏每日挑战的可靠因果 uplift；先测挑战参与、完成、次日回访，并提供固定种子/规则说明。 |

任何对照都应使用一致的版本、清晰的曝光定义和预先选定的核心指标；只看功能使用率不能推出留存提升。样本量不足时报告区间与限制，不把相关性写成因果。

## 未检索到可靠数据

- 没有找到能直接支持「移动端一局必须 3/5/10 分钟」的统一标准；产品样例跨度很大，故短出击时长应作为项目实验变量，而不是平台定律。[4][5]
- 没有找到可迁移到免费网页射击游戏的成就、图鉴、排行榜、每日挑战 D1/D7 提升百分比。Steam 页面列出的成就/功能标签只说明功能存在，不是留存实验结果。[4][5][6][7]
- 没有找到能普遍证明指数成长优于线性成长、或特定 pity 次数提升留存的同类因果数据；需要依据本项目经济与玩家测试做判断。
