## 1. 事实更正（阶段 3 方案必须遵守）

1. **× 撤回「突变词条有成熟产品先例」**（`research-mobile-shmup.md:85`）：所引网易产品分析全文无「每日 1 正 + 1 反 DEBUFF」表述，实际是「每日活动三子玩法」+「金羽毛三选一 BUFF」（后者与本项目升级三选一同构）。M3 想法可保留评审，但**出处须改为自研设计，不得声称业界验证**。
2. **× 撤回 Sky Force 具体数字**：4 星四条判定、30 张卡（6 限时/24 永久）仅有 C 级攻略来源，Wikipedia 只支持「关卡中获得星星」。范式（关卡评级 / 掉落式永久强化）可用，**数字不得写入设计参数**。
3. **× 更正虫姬条目**：「Gameplay 段为空」不实（该段正是 Maniac/受击自动放弹的出处）；「Hyper 是虫姬机制」不成立——阴性证据显示 Hyper 属怒首领蜂大往生系列，虫姬未见记载。评审时不得把 hyper 当虫姬可借鉴项。
4. **A 级升格：Battle Garegga rank 的失败模式**——原文「玩家被迫压火力、省子弹、**故意送命**以让最后几关仍可打」。这与本项目 `SCORE_AXIS`（涨分即涨难度）同构，是**必须预演的反面教材**：任何「得分/构筑越强则难度越高」的新模式都要有刹车。
5. **可精确化**：Ikaruga chain 25,600 上限、Touhou deathbomb 0.3s、graze 定义、Strikers 1945 结算评级（用时/金条/击坠）均为 A 级可引用；chain 重置条件是「错序」而非仅「错色」。
6. 元进程的**留存因果数据无任何可靠同类公开来源**，任何方案不得承诺「留存 +N%」。

## 3. 项目现状能力（评审硬约束，来自 inventory）

- **灰度不碰 UI 的口子**：URL 参数新模式（`?campaign=` / `?bossrush=1` 先例）、新关卡 JSON、新弹幕图案、技能/道具数值、得分曲线、HUD 新增指示（`js/hud.js` 独立）、toast 文案。
- **必然碰 `js/ui/**`**：主菜单入口/按钮、新面板、图鉴/机库/商城/成就页改动、帮助面板。
- **统一红线**（模式轴提案 §8）：① 密集弹幕必过 `setHostileBulletBudget`；② 不得新开乘算口子绕过软上限（SCORE_AXIS / 连锁 0.7^depth / POWERUP_DURATION）；③ 默认路径逐位一致；④ 44px 触控 + 帮助面板模态不回归。
- 已知坑：首局帮助面板吞首次点击、Boss 贴图懒加载、版本化完整性计数**新增模块必须同步 `deploy-versioning`**、涨分即涨难度（Garegga 反面教材）。
